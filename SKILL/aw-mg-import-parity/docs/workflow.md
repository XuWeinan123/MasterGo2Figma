# MG 导入保真度修复工作流

本文档是执行 AW MG Import Parity 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的可视化投影。

## 输入与产物

- 输入：新的 `.mg` 测试文件、对应基准 zip，以及包含 mg、zip、截图三类页面的 Figma 链接。
- 产物：经过全 fixture 回归的解码器或 importer 修复、三份同步文档，以及修复前后数字对照和重导入验证说明。

## 执行步骤

1. 确认测试文件和三类 Figma 页面，读取目标仓库 `AGENTS.md`、解码器规范和逆向日志。
2. 建立证据职责：截图是渲染基准，zip 是结构辅助，mg 导入是修复对象；不得混用三者下结论。
3. 使用比较工具生成基线，按 deep prop、font、geometry、transform 和 index 分类差异，并保存修复前计数。
4. 需要修解码器时，以 record ID、字节证据和 zip 交叉表逆向字段；先定义新语法边界，再小步修改 `mgPackage.js`。
5. 每次解码器修改后运行主 fixture、全部其他 fixture A/B、无 zip fixture 结构摘要、Node 测试和两端构建；added 集合必须为零。
6. 对 mg、zip、截图同名 frame 做三联视觉比较。
   - 只有 mg 错：继续解码器定位。
   - zip 与 mg 一起错：转向 importer 取证，检查真实节点树与删除类逻辑。
7. importer 修复后重新构建，并用顶层块数或重导入证据验证比较器看不到的删除问题；清理 Figma 中的临时测试节点。
8. 同步解码器规范、逆向日志、当前 parity 状态和自动记忆，输出修复前后数字表及残差。

## 停止条件

- `.mg`、zip 或三类页面无法对应时停止确认。
- 缺少字节级证据时不得把猜测写成解码规则。
- 任一 fixture 出现新增回归、测试失败数超出既有基线或构建失败时不得交付。
- 插件无法由当前 Agent 实际重导入时，明确把画布最终验证留给用户，不伪造成功。

## 最终交付

交付解码器与 importer 分列的修复清单、各差异类别前后计数、全量回归结果、保留残差、同步文档和使用新构建重新导入的提醒。
